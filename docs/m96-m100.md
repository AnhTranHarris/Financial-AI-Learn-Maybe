# Dusty Dragon M96–M100 — Local Runtime Foundation and Basic UI

## Objective

M96–M100 begins assembling the M0–M95 research, analysis, forecast, risk and MT5 contracts into a
local Windows application. This phase deliberately stops before an autonomous execution loop. It
builds the smallest truthful operator surface needed to discover MT5 terminals, inspect broker
state, make an exact strategy selection, explain authority gates and request safe Codex assistance.

The elegant production interface remains a separate project. This shell is disposable: trading
logic belongs behind application ports, never inside Tkinter callbacks.

## Milestones

| Milestone | Capability | Proof boundary |
|---|---|---|
| M96 | Bounded Windows MT5 inventory | Running-process, Registry, standard-location and manual evidence are deduplicated by executable path. Discovery neither launches nor assigns an account. |
| M97 | Read-only terminal truth | Explicit connection reads terminal build, broker/server, masked login, account mode, balance/equity/margin, symbols, positions, orders and bounded deal history. No order method exists. |
| M98 | Strategy and mode selection | Compatibility is explicit by broker symbol/category. Backtest, Demo and Live gates are revocable and bound to terminal, account, symbol, strategy and exact commit evidence. |
| M99 | Codex assistance boundary | Reports are sanitized, ephemeral and read-only. Development requires human confirmation, a clean Git worktree, no active trading runtime and workspace-only writes. |
| M100 | One-window desktop shell | Terminal, account, symbol, strategy, mode, Start, Stop Entries, Emergency Halt, compact status and Codex controls are represented without moving trading logic into the UI. |

## Terminal discovery

The inventory accepts four evidence sources:

- currently running `terminal.exe` or `terminal64.exe` processes;
- Windows uninstall records whose product identity is MetaTrader 5;
- bounded searches under Program Files and the user's local Programs directory;
- terminal paths entered explicitly by the user.

Filesystem traversal has both depth and directory-count bounds. Invalid paths and non-terminal
executables are ignored. Multiple sources collapse into one `TerminalInstallation`, retaining
running process identifiers and the `/portable` hint when observed.

MetaQuotes documents that Python `initialize()` accepts an exact terminal executable path and a
portable-mode flag. The official terminal documentation also distinguishes portable storage from
the normal user data directory:

- <https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py>
- <https://www.metatrader5.com/en/terminal/help/start_advanced/start>
- <https://www.metatrader5.com/en/terminal/help/start_advanced/structure>

## Read-only broker snapshot

After the user selects **Connect**, the reader calls only MT5 inventory surfaces:

- `terminal_info()` and `version()`;
- `account_info()`;
- `symbols_get()`;
- `positions_get()`;
- `orders_get()`;
- bounded `history_deals_get()`.

It never calls `login()`, `symbol_select()`, `order_check()` or `order_send()`. Optional state read
failures become visible warnings rather than being silently represented as proven empty state.
Symbol inventory failure blocks connection because the selection UI cannot operate honestly without
the broker's exact symbol names and economics.

## Revocable mode gates

Backtest becomes selectable only for a connected terminal and an explicitly compatible translated
or later-stage strategy. Demo additionally requires:

- a DEMO account;
- trading and Expert permissions;
- an exact qualification binding;
- a passing backtest;
- native MT5 parity;
- explicit user confirmation of the Demo terminal.

Live remains locked in this phase even if a caller constructs favorable Demo claims. The gate emits
`live_execution_not_implemented`. Future Live engineering must retain the six-desk campaign,
explicit capital/terminal approval, independent risk review and session-bound authority; a UI state
alone can never authorize a broker write.

## Codex boundary

M99 uses the documented local Codex non-interactive interface rather than embedding a broker-aware
agent. `codex exec` supports an explicit read-only or workspace-write sandbox, ephemeral runs and
stdin context. Dusty relies on a separately configured local Codex login and does not accept or store
an OpenAI API key.

Official documentation:

- <https://developers.openai.com/codex/non-interactive-mode>
- <https://developers.openai.com/codex/codex-sdk>

The support bundle contains the exact code commit, selection, mode gates and a compact account and
runtime status. It excludes the account login and raw terminal path, hashes terminal identity, and
recursively redacts credential-shaped keys. Codex has no reference to `DemoMT5ExecutionAdapter` and
no MT5 module object.

The CLI implementation sits behind `CodexCLIReporter`. A later interface may adopt the stable Codex
Python SDK without changing terminal, selection or authority semantics.

| Reference | M96–M100 lesson | Boundary retained |
|---|---|---|
| Kronos | Model/artifact identity must be visible before model evidence is trusted | No model is implied by an adapter name |
| Chronos-2 | Forecast context and horizon remain part of selection identity | The UI cannot create forecast authority |
| Uni2TS/Moirai | Evaluation belongs to rolling evidence rather than the presentation layer | No scoring inside the UI |
| Vibe-Trading | Operator halt, exact symbol identity and liveness failures must be visible | No broad agent/runtime import |
| Qlib | Keep data, model, strategy, portfolio and execution loosely coupled | One application controller coordinates ports without merging authority layers |
| RD-Agent | Development needs an evaluated workspace and feedback boundary | Codex edits are isolated from a running trading process |
| TradingAgents | Durable state and checkpoints matter more than visual debate | LLM conversation never becomes broker permission |
| ai-hedge-fund | One cycle should eventually connect data through execution and record | M100 does not pretend the cycle is complete |
| Automaton | Heartbeat, resource tiers and immutable laws belong in runtime coordination | Replication, self-funding and sovereign modification remain rejected |
| Microsoft Agent Framework | Custom clients need explicit sandbox, approval and durable workflow boundaries | The small local port is retained instead of importing a general framework |

## Honest end state

M100 is operationally useful for local inventory, broker-state inspection, mode explanation and Codex
support. It is not an autonomous bot and does not enable the Start button without a configured
`RuntimeControlPort`. The next correction phase must build the authoritative restartable runtime that
unifies V2 strategy execution, V3 analysis, probabilistic forecasting, risk/portfolio allocation,
immutable authorization, broker reconciliation and outcome learning.
