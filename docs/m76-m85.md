# Dusty Dragon M76–M85 — MT5 Indicator, Chart and Trade Intelligence

M76–M85 adds a governed analytical language for MT5 native indicators, user-installed custom
indicators, price structure and chart objects. It carries that language into typed long/short
entry, hold, protection and exit decisions, native MT5 evidence, Demo Desk drift control and a
firm-mandate certification.

This phase does **not** authorize live-money trading and does not claim that operational M75 or
M85 evidence has already been generated. M76 implementation is software readiness; operational
certification still requires the target Windows/MT5 environment.

The governing rule is:

> An analytical tool is a versioned, falsifiable dependency. It may inform a trade only while its
> identity, timing, semantics, native behavior and incremental value remain proven.

## M76 — Analytical Tool Constitution and Durable Registry

Implemented in `src/dusty/analytical_tools.py`.

Dusty represents native indicators, custom indicators, price structures and drawing tools with:

- immutable identity and version;
- role such as regime, direction, entry, hold, exit or protection;
- source/origin;
- typed parameters;
- named buffer semantics;
- warm-up requirement;
- source/artifact path and SHA-256 identity;
- use/modification license boundary;
- deterministic fingerprint.

The SQLite registry records an append-only lifecycle:

```text
DISCOVERED -> QUARANTINED -> CHARACTERIZED -> RESEARCH_APPROVED
           -> CHALLENGER -> CERTIFIED_DEPENDENCY
```

Later outcomes may produce `REGIME_RESTRICTED`, `DEGRADED`, `SUSPENDED`, `RETIRED` or
`INVALID`. Terminal states cannot be revived because of a recent attractive result. Retired and
invalid tools remain in history so Dusty cannot hide failed research or repeatedly rediscover it.

Custom indicator files may only be hashed inside an explicitly approved indicator root. An EX5
requires declared buffer semantics before it can become an analytical tool.

## M77 — Native MT5 Indicator and Chart Bridge

Implemented in:

- `src/dusty/mt5_analysis.py`;
- `mt5/DustyChartProbe.mq5`.

The indicator bridge generates a small, per-tool, tester-only MQL5 probe. Per-tool generation is
required because MT5 Strategy Tester must receive a literal custom-indicator dependency through
`iCustom()`/`tester_indicator`. The generated probe:

- refuses normal-terminal initialization;
- creates one declared native or custom handle;
- waits for calculated buffers;
- reads completed-bar values through `CopyBuffer()`;
- exports source-open and availability time separately;
- binds terminal build, symbol, timeframe and tool fingerprint;
- exposes no broker-write function.

The native catalog includes SMA, EMA, ATR, RSI, MACD, ADX, Bollinger Bands, Stochastic, CCI,
Momentum, OBV, MFI, Ichimoku and standard deviation.

`DustyChartProbe.mq5` is read-only. It inventories chart symbols/timeframes, attached indicators,
graphical-object types, anchors and levels. Chart display objects do not automatically become
market evidence.

## M78 — Custom Tool and Public Strategy Onboarding

Implemented across `analytical_tools.py`, `mt5_analysis.py` and `strategy_v3.py`.

Trust classes are explicit:

| Material | Permitted action | Prohibited claim |
|---|---|---|
| Licensed MQ5 source | inspect, compile, version and test | profitable because source exists |
| EX5 plus trusted descriptor | execute and study declared buffers | knowledge of opaque internals |
| EX5 without descriptor | hash and quarantine | guessed buffer meaning or execution use |
| Public executable strategy | quarantine and translate | direct execution authority |

Online strategy claims are captured as structured rules with source URL and capture time. Missing
definitions block research readiness. Supplied executable source is never accepted directly into
the runtime.

## M79 — Point-in-Time and Behavioral Validity

Implemented in `analytical_tools.py`, `chart_intelligence.py` and `price_structure.py`.

Dusty classifies analytical time behavior as:

- `CAUSAL_COMPLETED_BAR`;
- `CURRENT_BAR_UNSTABLE`;
- `REPAINTING`;
- `FUTURE_DEPENDENT`;
- `UNDETERMINED`.

Prefix revisions expose historical rewriting. A future timestamp or changed completed historical
value invalidates the tool even when its reported performance is positive.

Chart objects carry aware anchor timestamps and a separate `known_at`. A chart object cannot use
an anchor from the future. Supported analytical vocabulary includes lines, channels, Fibonacci,
Gann, Pitchfork, Elliott/cycle annotations, zones and arrows; decorative text/interface controls
remain non-analytical.

Price-structure primitives confirm swing highs/lows only after the required right-hand bars become
available. Trend classification and generated trendlines use those confirmed pivots, so adding
future bars cannot retroactively award Dusty an earlier chart insight.

## M80 — Unified Market Analysis Graph

Implemented in `src/dusty/chart_intelligence.py`.

`MarketAnalysisGraph` combines raw market inputs, indicator buffers and chart-derived values using
a small typed DAG. It supports numeric transforms, comparisons, crossovers and boolean ALL/ANY/NOT
composition.

The graph:

- must be topologically ordered and acyclic;
- binds every analytical-tool fingerprint;
- rejects missing inputs;
- rejects future-known snapshot evidence;
- distinguishes numeric and boolean operations;
- handles crossover only when the previous observation exists;
- produces a deterministic graph fingerprint.

Chart rendering, colors and zoom are not semantic authority. A future visual model may challenge
structured analysis, but trading decisions use exact price/time/object/buffer evidence.

## M81 — Strategy IR v3 and Complete Trade Reasoning

Implemented in `src/dusty/strategy_v3.py`.

`StrategySpecV3` binds one graph and immutable tool set to separate policies for:

- long/short entry;
- hold validity;
- partial exits;
- full exits;
- protection tightening;
- initial stop, target, trailing and breakeven;
- market, limit, stop or stop-limit entry style.

The lifecycle emits typed directives:

```text
WAIT
ENTER_LONG / ENTER_SHORT
HOLD
TIGHTEN_PROTECTION
PARTIAL_EXIT
EXIT
```

Conflicting long and short signals fail closed. Invalid tools block new entries and qualify an exit
for an exposed position. A missing hold thesis closes rather than silently continuing. Stop widening
remains constitutionally prohibited.

## M82 — Modification, Restriction and Retirement

Implemented in `src/dusty/analytical_tools.py` and `src/dusty/tool_evaluation.py`.

Dusty compares a complete strategy with a time-aligned ablation that removes one tool. It evaluates
incremental expectancy, drawdown, rules, regime deltas and evidence count.

Possible decisions are:

- retain;
- restrict to a proven regime;
- modify through a stated repair hypothesis;
- retire;
- collect more evidence.

A modification is a new child fingerprint with parent lineage and rationale. It is never a hot patch
of a deployed Champion. Opaque EX5 internals cannot be modified.

## M83 — Native Strategy Tournament

Implemented in `src/dusty/analysis_runtime.py` and `src/dusty/tool_evaluation.py`, with native
evidence supplied through M77 and the M67 research laboratory.

The analysis replay binds the exact graph, tool set and StrategySpecV3, walks chronological
point-in-time snapshots, and emits the same entry/hold/protection/partial-exit/full-exit directives
used by the Demo runtime. It is a semantic reference, not a replacement for the realistic account
ledger or native Strategy Tester.

A candidate must pass:

- validation and untouched-test expectancy;
- adequate untouched trade count;
- profit-factor, drawdown and concentration limits;
- parameter-neighborhood stability;
- valid analytical dependencies;
- native indicator parity;
- native execution parity;
- zero trading-rule violations.

Profitable native-parity failures and profitable governance violations are rejected. Every trial,
including failed combinations, remains part of search-breadth evidence.

## M84 — Frozen Demo Analysis and Broker Capability Expansion

Implemented in:

- `src/dusty/analysis_certification.py`;
- `src/dusty/order_intent.py`;
- `src/dusty/position_actions.py`.

Runtime observations compare exact strategy, graph and ordered tool fingerprints with the frozen
Demo Champion. Uncertified state, hash drift, missing native value or stale value blocks new entries.
Position supervision remains required.

The immutable intent/preflight boundary now models broker-supported:

- market orders;
- limit orders;
- stop orders;
- stop-limit orders;
- long and short geometry;
- pending-order expiration;
- broker-native profit-at-stop, margin and `order_check()`.

Only the existing `DemoMT5ExecutionAdapter` owns `order_send()`. Pending capability does not create a
second send surface and does not authorize live trading.

Position management uses immutable, separately preflighted actions for stop tightening, partial
close, full close and pending-order cancellation. These actions share the same crash-safe ledger and
the same single Demo execution adapter. Stop widening is rejected before any broker connection.

## M85 — Firm Mandate and Indicator/Chart Certification

Implemented in `src/dusty/analysis_certification.py`.

`FirmMandate` is fingerprinted before evaluation. It defines independent-window count, minimum
trades, positive net expectancy, profit factor, drawdown, concentration and six required Demo Desk
passes.

Certification requires:

- exact-commit evidence for M76–M84;
- a real M75 operational-proof hash;
- at least one certified analytical dependency;
- causal completed-bar behavior;
- native indicator parity;
- backtest/demo parity;
- unchanged artifact identity;
- all independent windows passing the mandate;
- six individually passing desks;
- no desk rule violation.

A full pass returns:

```text
indicator_chart_certified = true
demo_strategy_certified = true
live_compatible_research_package = true
live_write_authorized = false
```

Live-money permission remains a separate future certification and human capital decision.

## Operational evidence still required

Cloud CI proves deterministic contracts and injected broker behavior. It cannot prove:

- compilation of generated MQL5 probes in the user's terminal;
- custom EX5 compatibility or buffer truth;
- chart-object behavior in that terminal build;
- native indicator values;
- native Strategy Tester behavior;
- real demo pending/market fills;
- six passing Demo Desk generations;
- profitability.

Those observations must be produced on the target Windows PC and evaluated without changing the
mandate or tolerances after results are known.
